**Release Date:** 23 November 2026

<div style="background-color: AntiqueWhite; font-style: italic; padding: 15px;">
    <p style="margin-top: 0;"><strong>Note:</strong> v5.0.0 is the first major release since v4.0.2 (March 2026). Its primary goals were a new Bootstrap 5.3 interface, the removal of long-deprecated code and features, and a broad sweep of security, permission and data-integrity fixes. It replaces the three release candidates (<a href="/release-notes/5.0.0-rc1.html">rc1</a>, <a href="/release-notes/5.0.0-rc2.html">rc2</a> and <a href="/release-notes/5.0.0-rc3.html">rc3</a>), which are now deprecated, and includes all of their changes plus the fixes made since rc3.</p>
    <p>Changes that affect upgrades or Add On modules:</p>
    <ul style="font-style: normal; margin-bottom: 0;">
        <li>PHP 8.3 is the minimum. The installer checks the PHP extensions web2project needs: <code>ctype</code>, <code>filter</code>, <code>gd</code>, <code>json</code>, <code>mysqli</code> and <code>session</code> are required.</li>
        <li>Run <code>composer install --no-dev</code> after upgrading: Carbon moves to 3.x and <code>ircmaxell/password-compat</code> is removed.</li>
        <li><em>Apply System Updates</em> runs migrations 063–078. They stop at the first failed statement and report it in full. Migration 074 drops the contact update-request columns, 075 replaces apostrophes saved as <code>&amp;#039;</code>, and 078 resets project colours that aren't six-digit hex codes. Migration 077 makes login names unique: where two users share one, the newer accounts are renamed to <code>&lt;name&gt;-&lt;user id&gt;</code> and each rename is recorded in History.</li>
        <li>Bootstrap 5.3 is the only theme. The w2p-snowball and wps-redmond themes and theme selection are gone.</li>
        <li>Removed: the 66 functions in <code>includes/deprecated_functions.php</code> and the 37 deprecated class aliases (<code>CAppUI</code>, <code>CDate</code>, <code>DBQuery</code> and others), PDF output, file check-in/check-out, file versions and file e-mail notifications, and the contact self-update request. Add On modules that still use any of these will stop with errors.</li>
        <li><code>index.php</code> only loads a module's pages and runs its <code>dosql</code> and <code>do_*</code> handlers when the module is active and the user can access it, and every request that changes data must carry the <code>__nonce</code> form token.</li>
        <li>Translation files are read as data instead of being run with <code>eval()</code>.</li>
        <li>See <a href="/docs/installation.html#upgrading-to-v50">Upgrading to v5.0</a> and <a href="/docs/upgrading-modules-to-5.html">Updating Add On Modules for v5.0</a> before you upgrade.</li>
    </ul>
</div>

## New Features

* New Bootstrap 5.3 interface
  * Bootstrap 5.3.8 is bundled with the application, so no CDN is needed
  * NiceAdmin-style header, sidebar, colours and typography, using the bundled Nunito Sans and Poppins fonts and Bootstrap Icons
  * New sign-in, sign-up and lost-password pages
  * Layout tables replaced with Bootstrap markup in every module, the shared templates and the installer
  * A print stylesheet, so pages print cleanly from the browser in place of the old PDF export ([#393](https://github.com/web2project/web2project/issues/393))
  * The date picker is restyled to match, and its button is a Bootstrap icon button ([#567](https://github.com/web2project/web2project/issues/567))
* Installer
  * Checks each PHP extension web2project uses, marks it required or optional and says what it's for ([#290](https://github.com/web2project/web2project/pull/290), based on work by moisseev)
  * Warns when `file_uploads` is off in `php.ini`
* Projects
  * New "Tasks (All)" tab on the project view showing active and inactive tasks together in tree order (based on work by Klaus Buecher)
  * Inactive tasks now have their own row colour and an entry in the task key
  * Project budgets are shown on the project view again
* Tasks
  * The "show inactive tasks" link on the Tasks list now works, as a "show all tasks" / "show active tasks" toggle (based on work by Klaus Buecher)
  * Resources assigned on a task's "Other resources" tab are saved again; nothing had saved them since v3.2 (based on work by Klaus Buecher)
* Files
  * The Folder Explorer is back as a Folders tab ([#406](https://github.com/web2project/web2project/issues/406), [#407](https://github.com/web2project/web2project/issues/407), [#408](https://github.com/web2project/web2project/issues/408)), and the Add/Edit File form has a folder field for moving files between folders ([#405](https://github.com/web2project/web2project/issues/405))
  * The Files list is grouped under project headings and hides files from projects and tasks the user isn't allowed to see
  * New Owner and Category filters on the Files page, next to the Project filter
* Calendars shade non-working days from `cal_working_days` and holidays
* The header search box runs SmartSearch directly, and SmartSearch is hidden from the menu (migration 071)
* Public sign-up has self-hosted bot protection: a proof-of-work puzzle, a hidden-field trap and timing checks ([#363](https://github.com/web2project/web2project/issues/363))
* Lost password works again and generates unguessable passwords
* Custom fields work on users, and calendar (event) custom fields work again
* The contact page shows tabs added by Add On modules, such as Todos ([#561](https://github.com/web2project/web2project/issues/561))
* A German help page; the help window links to the docs site, GitHub Discussions and the issue tracker

## Fixes/Bugs Closed

* Security
  * Role changes are checked per account and per role. Without System edit rights, users can't change their own roles, grant or remove the Administrator role, or change an Administrator's roles ([GHSA-qqx6-f7cc-3wf2](https://github.com/web2project/web2project/security/advisories/GHSA-qqx6-f7cc-3wf2), reported by M4ru-0x03)
  * Saving an account keeps the fields the form doesn't edit (user type, parent, login name, password hash and linked contact), and sign-up always creates a new, normal account ([GHSA-65x8-6jcq-fc5r](https://github.com/web2project/web2project/security/advisories/GHSA-65x8-6jcq-fc5r))
  * Bulk task actions, task saves and new tasks check the task and its project ([GHSA-48ww-5h48-vwx9](https://github.com/web2project/web2project/security/advisories/GHSA-48ww-5h48-vwx9), reported by M4ru-0x03); moving a task to another project checks permissions first ([#472](https://github.com/web2project/web2project/issues/472))
  * Task logs: edit and delete rights are checked against the stored log, not the posted creator ([GHSA-xcpx-p68j-gm7w](https://github.com/web2project/web2project/security/advisories/GHSA-xcpx-p68j-gm7w))
  * Forums: watches and watch e-mails only for forums the user can read ([GHSA-qp43-fcwc-p3j3](https://github.com/web2project/web2project/security/advisories/GHSA-qp43-fcwc-p3j3)); a topic is only shown, replied to or posted in after a check on its own forum and project; only a message's author or an administrator can edit or delete it
  * SQL injection: search terms are quoted in every LIKE clause, so `%` and `_` now match literally ([GHSA-98hj-h8rw-w56m](https://github.com/web2project/web2project/security/advisories/GHSA-98hj-h8rw-w56m), reported by Yescrypt; [GHSA-mj5m-6227-52vv](https://github.com/web2project/web2project/security/advisories/GHSA-mj5m-6227-52vv), reported by p-w); also fixed in preferences, the Users list letter filter, sort parameters, SmartSearch, the public sign-up e-mail check, the contacts duplicate check ([#402](https://github.com/web2project/web2project/issues/402)) and bound strings put into SQL
  * Stored XSS: names are escaped in list tables, view pages, calendars and task lists ([#546](https://github.com/web2project/web2project/issues/546)), forum titles, bodies and author names ([#533](https://github.com/web2project/web2project/issues/533)), the selector pop-up and drop-down labels, SmartSearch results, and URL fields ([#401](https://github.com/web2project/web2project/issues/401)); tooltips show their text as text, so a name holding markup no longer runs when hovered; project colours must be six-digit hex codes
  * Reflected XSS: the Projects Gantt tab builds its chart URL from numbers and flags only ([#542](https://github.com/web2project/web2project/issues/542))
  * CSRF: every request that changes data needs the session's form token, including logout, ending sessions and module admin links ([#400](https://github.com/web2project/web2project/issues/400))
  * `index.php` only loads pages and runs `dosql`/`do_*` handlers of active modules the user can access ([#463](https://github.com/web2project/web2project/issues/463), [#547](https://github.com/web2project/web2project/issues/547)), and refuses unknown or malformed handlers
  * Sessions: the id is regenerated at login and no longer put in redirect URLs; the cookie is Secure, HttpOnly and SameSite
  * Passwords: the current password is checked with `password_verify()`, saving a user no longer re-hashes it ([#386](https://github.com/web2project/web2project/issues/386)), legacy MD5 hashes are compared with `hash_equals()` ([#474](https://github.com/web2project/web2project/issues/474)), and the sign-up e-mail no longer contains the password
  * Calendar feeds use random tokens and stop for users who can't log in ([#436](https://github.com/web2project/web2project/issues/436))
  * Translation files are parsed instead of run with `eval()` ([#313](https://github.com/web2project/web2project/issues/313)), and the translation editor only writes files for installed modules and languages and requires the form token
  * Smaller fixes: the Active Sessions tab checks the session id, `CAppUI::isActiveModule()` no longer builds SQL from the module name ([#457](https://github.com/web2project/web2project/issues/457)), the inactive tasks tab and History list filter by permission in SQL ([#476](https://github.com/web2project/web2project/issues/476), [#477](https://github.com/web2project/web2project/issues/477)), the Files form stops including the HelpDesk add-on's config.php ([#466](https://github.com/web2project/web2project/issues/466)), and `w2PgetParam()` drops a filter that never matched ([#403](https://github.com/web2project/web2project/issues/403))
* Users, permissions and LDAP
  * On new installs, the Project worker role has Access, View, Add and Edit on the non-admin modules; before, it couldn't open any module
  * Login names are unique (migration 077) ([#438](https://github.com/web2project/web2project/issues/438)); sign-up stores the name it checked
  * User and Calendar permissions can be granted, Users editors can save other users' preferences, and the "delete User" action is back ([#385](https://github.com/web2project/web2project/issues/385))
  * LDAP: new users always get a contact and a password hashed once, and a login fails cleanly when the local user can't be created ([#320](https://github.com/web2project/web2project/issues/320), [#440](https://github.com/web2project/web2project/issues/440))
  * Logins are recorded and stay open until they end; logouts are recorded; activity time is updated on every request ([#445](https://github.com/web2project/web2project/issues/445))
  * A refused delete no longer runs its cleanup (for example, removing a user's login and preferences)
* Upgrades and the database
  * Works with MySQL 8's default `sql_mode`, including strict mode and dotProject conversions ([#532](https://github.com/web2project/web2project/issues/532))
  * Upgrades stop at the first failed statement and report the migration, statement and error; a failed migration isn't recorded, so it can simply be run again
  * Fixes to migrations 002, 004, 012, 033, 046, 050/051, 056, 059, 070 and 071; migration 070 brings databases upgraded from 4.x in line with fresh installs, and 076 cleans zero dates in the login log ([#537](https://github.com/web2project/web2project/issues/537))
  * Apostrophes are no longer saved as `&#039;` (migration 075) ([#556](https://github.com/web2project/web2project/issues/556))
  * `insertObject()` writes `0`, `false` and empty text instead of dropping them ([#559](https://github.com/web2project/web2project/issues/559))
  * The Resources tables are fixed on new installs (migration 068)
  * Database version is now 78
* Projects and tasks
  * Task logs, Child Tasks and Task Logs tabs, task reminders, "Update projects status" and the project list for users without full department rights work again
  * Task dates moved by dependencies stay in UTC; re-parenting and moving tasks roll up dynamic dates and update task counts (fixes from Klaus Buecher)
  * History records each entry's project and lists it on the project tab ([#525](https://github.com/web2project/web2project/issues/525)); task logs follow their task between projects
  * Custom fields are only saved when a `store()` was given them ([#473](https://github.com/web2project/web2project/issues/473), [#527](https://github.com/web2project/web2project/issues/527))
  * A failed save is only restored into the edit page of the same record
  * List cells show "-" for a missing linked object instead of an empty link ([#558](https://github.com/web2project/web2project/issues/558))
* Gantt charts
  * All text is drawn in DejaVu Sans, so non-Latin names and CJK text render; the Today line, dependency arrows and narrow charts are fixed
  * The project Gantt tab and ProjectDesigner show every task; the sub-projects Gantt works on PHP 8
* Calendars, dates and reports
  * `w2p_Utilities_Date::convertTZ()`, `format()`, `getBeginWeek()`/`getEndWeek()`, `addDays()` across DST and the other date helpers return the right dates ([#519](https://github.com/web2project/web2project/issues/519), [#520](https://github.com/web2project/web2project/issues/520))
  * Calendars mark today; the week view shows the loaded week; recurring events no longer crash the day view ([#530](https://github.com/web2project/web2project/issues/530)), and hourly recurrences no longer all land on the first one
  * Reports open on the last two weeks, and the Task List report's previous and next buttons move the range ([#553](https://github.com/web2project/web2project/issues/553)); fixes to Project Statistics, Task Logs and Allocated User Hours ([#524](https://github.com/web2project/web2project/issues/524)); the cost reports no longer fail on a project without a start date
  * Tooltips show plain text, one line per field, instead of markup
* Files
  * Page links, project and category filters and the company Files tab work together; folders can't be moved into themselves and delete through the Files module ([#409](https://github.com/web2project/web2project/issues/409), [#410](https://github.com/web2project/web2project/issues/410), [#432](https://github.com/web2project/web2project/issues/432)); a duplicated file keeps its project and folder ([#411](https://github.com/web2project/web2project/issues/411))
* Mail and forums
  * Queued mail is sent, Cc/Bcc work ([#424](https://github.com/web2project/web2project/issues/424), [#425](https://github.com/web2project/web2project/issues/425)), accented subjects are no longer blank ([#523](https://github.com/web2project/web2project/issues/523)), and queuescanner.php no longer crashes on contacts ([#399](https://github.com/web2project/web2project/issues/399))
  * Forum BBCode renders on PHP 8 ([#531](https://github.com/web2project/web2project/issues/531)), the reply form shows the message being replied to ([#429](https://github.com/web2project/web2project/issues/429)), and message counts are kept
* Language packs
  * Fall back to English when a language isn't installed ([#495](https://github.com/web2project/web2project/issues/495), [#501](https://github.com/web2project/web2project/issues/501), [#502](https://github.com/web2project/web2project/issues/502), [#503](https://github.com/web2project/web2project/issues/503), [#504](https://github.com/web2project/web2project/issues/504)); "Non-working day" is translated ([#454](https://github.com/web2project/web2project/issues/454))
* PHP 8
  * A logged-in crawl of the core pages logs no PHP warnings or notices; fixes include `arraySelect()` taking its list by value ([#554](https://github.com/web2project/web2project/issues/554)), module install and remove ([#563](https://github.com/web2project/web2project/issues/563)), `Date_Span` (zero on PHP 8) replaced, and `loadFull()`'s parameter order

## Misc Changes/Improvements

* Removed
  * PDF output (reports, Gantt charts and forums) and the dead PDF code outside lib/ ([#392](https://github.com/web2project/web2project/issues/392))
  * File check-in/check-out ([#376](https://github.com/web2project/web2project/issues/376)), file change e-mail notifications and the file version field
  * The contact self-update request (`updatecontact.php`, `do_updatecontact.php`, migration 074)
  * The w2p-snowball and wps-redmond themes, and theme selection
  * `includes/deprecated_functions.php` (66 functions), the 37 deprecated class aliases and the remaining `db_*` helpers
  * The unused Projects list search and the Scrutinizer config
* Deprecated until v6.0: `getCriticalTasksInverted()`, `strUTF8Decode()`, `CAppUI::readFiles()`, `checkFileName()` and `loadCalendarJS()` ([#465](https://github.com/web2project/web2project/issues/465))
* `w2p_Exception_FileSystem` is now `w2p_Exceptions_FileSystem` ([#467](https://github.com/web2project/web2project/issues/467))
* Table prefixes are explicitly unsupported ([#427](https://github.com/web2project/web2project/issues/427))
* New helpers for Add On modules: `w2p_Database_Query::quoteLike()`, `w2PsafeOrderBy()`, `CAppUI::restoreObject($object)`, and `ListTable::addDividers()` for any `*_project` key ([#560](https://github.com/web2project/web2project/issues/560))
* Support links point to GitHub Discussions and the issue tracker instead of the old forums and Mantis
* Code cleanup: PHPDoc across all classes, modules and tests; removed commented-out and unreachable code; valid HTML5 with no deprecated tags; a PHPStan level 10 configuration and fixes
* Unit tests run on PHPUnit 11.5, including the include tests, with new tests for the fixes above
* Version set to 5.0.0 (Composer package 5.0)

## Open/Known Issues

* Uploaded files are stored inside the web root and protected only by an Apache 2.2-style `.htaccess` ([#394](https://github.com/web2project/web2project/issues/394), [#395](https://github.com/web2project/web2project/issues/395)). See [Security Notes](/docs/security-notes.html).
* [#535](https://github.com/web2project/web2project/issues/535) / [#536](https://github.com/web2project/web2project/issues/536) Converted dotProject sites lack some module rows and keep dotProject column types
* [#538](https://github.com/web2project/web2project/issues/538) `updateLogin()` logs "Undefined array key" warnings on every user save; [#555](https://github.com/web2project/web2project/issues/555) PHP 8.2 dynamic property deprecations remain in a few classes
* [#478](https://github.com/web2project/web2project/issues/478) A save refused for lack of permission shows an empty error message
* [#551](https://github.com/web2project/web2project/issues/551) Add On modules can't ship templates that `resolveTemplate()` finds
* [#392](https://github.com/web2project/web2project/issues/392) The PDF libraries and fonts are still in lib/ (planned for v6.0)
* The database layer (ADOdb) and date handling (PEAR Date) are old and due to be replaced.
* The unit test suite runs 587 tests (120 skipped) with 6 errors and 8 failures.
